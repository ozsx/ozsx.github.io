Chương 02 · Khởi động

🎲 Dự án 1 · Trò chơi đoán số

Dự án đầu tiên kết nối nhập liệu, biến khả biến, vòng lặp, match và Result. Với rand 0.9, dùng rng().random_range; đừng sao chép API rand 0.8 từ những tài liệu cũ.

So sánh & ghi nhớ: Nhập → phân tích → đối sánh → lặp

`Result` buộc bạn xem xét nhánh lỗi. `continue` bỏ lượt nhập sai; `break` kết thúc khi đoán đúng.

use rand::Rng;
use std::{cmp::Ordering, io};
fn main() {
    let secret = rand::rng().random_range(1..=100);
    loop {
        let mut s = String::new();
        io::stdin().read_line(&mut s).expect("Đọc lỗi");
        let guess: u32 = match s.trim().parse() {
            Ok(n) => n, Err(_) => continue,
        };
        match guess.cmp(&secret) {
            Ordering::Less => println!("Nhỏ quá!"),
            Ordering::Greater => println!("Lớn quá!"),
            Ordering::Equal => { println!("Thắng!"); break; }
        }
    }
}

Chương 03 · Nhập môn

📦 Biến, mut và phạm vi

Rust ưu tiên bất biến: let tạo binding không thể gán lại; let mut cho phép thay đổi; khai báo let mới với cùng tên tạo shadowing.

So sánh & ghi nhớ: let ≠ let mut ≠ const

`let` có thể suy luận kiểu, giá trị xác định lúc chạy; `const` phải ghi kiểu và là biểu thức hằng; shadowing tạo binding mới, khác gán lại.

fn main() {
    let x = 5;
    let x = x + 1; // shadowing
    let mut y = 3;
    y += 1;
    println!("{x}, {y}");
}

Chương 05 · Quyền sở hữu

🔑 Ownership, move và borrowing

Mỗi giá trị có chủ sở hữu; khi chủ sở hữu rời phạm vi, tài nguyên được dọn dẹp. Chuyển String theo giá trị thường move; &T cho mượn chỉ đọc, &mut T cho mượn có thể sửa với quy tắc độc quyền.

So sánh & ghi nhớ: Move → chủ cũ không còn dùng giá trị

`String` thường move khi gán hoặc truyền theo giá trị; các kiểu `Copy` như i32 được sao chép. Trong cùng thời điểm không thể vừa có tham chiếu &mut đang hoạt động vừa truy cập qua tham chiếu xung đột.

fn print_len(s: &str) {
    println!("{}", s.len());
}
fn main() {
    let mut name = String::from("Rust");
    print_len(&name); // mượn chỉ đọc
    let edit = &mut name;
    edit.push_str(" lang");
    println!("{name}");
}

Chương 06 · Kiểu phức hợp

🔤 Chuỗi String và &str

String sở hữu buffer UTF-8 có thể phát triển; &str là lát cắt mượn dữ liệu UTF-8. len() trả về byte, không phải số ký tự Unicode; không truy cập chuỗi bằng chỉ mục nguyên.

So sánh & ghi nhớ: String: ptr + len + capacity · &str: ptr + len

String sở hữu dữ liệu; &str là view chỉ đọc. Trên hệ 64-bit phổ biến, metadata tương ứng thường 24 và 16 byte; không tính vùng dữ liệu mà chúng trỏ tới.

fn greet(name: &str) {
    println!("Chào {name}");
}
fn main() {
    let mut s = String::from("Việt");
    greet(&s);
    println!("{} bytes", s.len()); // 6
    s.push_str(" Nam");
}

Chương 08 · Kiểu phức hợp

🎯 Match, if let và patterns

match đối sánh mẫu có kiểm tra bao phủ đầy đủ các trường hợp. if let phù hợp khi chỉ quan tâm một nhánh; let else hữu ích để thoát sớm khi mẫu không khớp.

So sánh & ghi nhớ: match = vét cạn · if let = nhánh quan tâm

`match` thường cần xử lý mọi variant; nhánh `_` gom trường hợp còn lại. Guard `if` đặt điều kiện phụ cho mẫu.

fn main() {
    let x = Some(7);
    match x {
        Some(n) if n > 5 => println!("Lớn: {n}"),
        Some(n) => println!("Nhỏ: {n}"),
        None => println!("Không có"),
    }
}

Chương 09 · Generics & traits

🔧 Methods và impl

impl gom các phương thức gắn với kiểu; &self mượn bất biến, &mut self mượn khả biến, self lấy quyền sở hữu. Hàm liên kết như new không cần tham số self.

So sánh & ghi nhớ: self · &self · &mut self

`self` tiêu thụ receiver; `&self` chỉ đọc; `&mut self` chỉnh sửa receiver qua mượn độc quyền. Rust không dùng inheritance kiểu lớp truyền thống.

struct Counter { n: u32 }
impl Counter {
    fn new() -> Self { Self { n: 0 } }
    fn tick(&mut self) { self.n += 1; }
}
fn main() {
    let mut c = Counter::new();
    c.tick();
    println!("{}", c.n);
}

🔁 Closures và iterators

}

Chương 20 · Đồng thời

🧵 Threads, channels và mutex

Rust dùng Send và Sync cùng ownership để loại trừ data race trong Safe Rust, nhưng vẫn cần tránh deadlock và lỗi phối hợp logic. Channel chuyển thông điệp; Mutex bảo vệ trạng thái chia sẻ.

So sánh & ghi nhớ: message passing vs shared state

Channel trao đổi thông điệp có quyền sở hữu; Arc<Mutex<T>> chia sẻ trạng thái có khóa. Không giữ lock lâu hơn cần thiết.

use std::{sync::{Arc, Mutex}, thread};
fn main() {
    let count = Arc::new(Mutex::new(0));
    let shared = Arc::clone(&count);
    let h = thread::spawn(move || {
        *shared.lock().unwrap() += 1;
    });
    h.join().unwrap();
    println!("{}", *count.lock().unwrap());

🌐 Dự án 3 · Web server thread pool

Dự án tổng hợp sử dụng TcpListener, yêu cầu HTTP tối giản, worker threads và channel để quản lý công việc. Phục vụ học tập, không phải server production với bảo mật, timeout và HTTP đầy đủ.

So sánh & ghi nhớ: socket → request → worker → response

Ví dụ này xử lý tuần tự để minh họa I/O; một thread pool hoàn chỉnh còn cần hàng đợi, đóng worker an toàn và xử lý lỗi. Hãy xem toàn văn chương 24 của nguồn để triển khai đầy đủ.

use std::io::{Read, Write};
use std::net::TcpListener;
fn main() -> std::io::Result<()> {
    let listener = TcpListener::bind("127.0.0.1:7878")?;
    for stream in listener.incoming() {
        let mut stream = stream?;
        let mut buf = [0; 1024];
        let _ = stream.read(&mut buf)?;
        stream.write_all(b"HTTP/1.1 200 OK\r\nContent-Length: 2\r\nConnection: close\r\n\r\nOK")?;
    }
    Ok(())
}
